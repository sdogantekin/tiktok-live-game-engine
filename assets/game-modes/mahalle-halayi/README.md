# Mahalle Halayı art assets

Stylized low-poly, toy-like diorama: colourful, warm, chunky silhouettes, flat shading, no textures. The
assets are generated by Blender scripts so they are reproducible and reviewable as code; the committed
`.glb` files are what the web app loads (ADR-008: editable source, optimized runtime GLB).

| What | Where |
|---|---|
| Blender scripts (the source of truth) | `scripts/` (`assetlib.py`, `build_character.py`, `build_crowd.py`, `build_courtyard.py`) |
| Editable `.blend` files (saved by the scripts) | `source-blend/` |
| Runtime GLBs | `apps/web/public/game-modes/mahalle-halayi/models/` |
| Names, clips and budgets the app relies on | `apps/web/src/game-modes/mahalle-halayi/assets.manifest.ts` |
| Placement of every piece, avatar looks, effect recipes | `apps/web/src/game-modes/mahalle-halayi/scene-config.ts` |

## Rebuild

```bash
pnpm assets:build   # needs Blender; set BLENDER=/path/to/Blender if it is not in /Applications
pnpm test           # validates the GLBs against the budgets and naming contract
```

Each script checks its own budgets (triangles, height, feet on the ground, bone count, required pieces) and
fails the build if one is violated.

## Style guide (the "concept sheet")

- **Shape language:** big heads, short chunky limbs, simple primitives, 6–8 segment curves. Silhouettes must read at phone size.
- **Material:** one shared material per file; colour lives in vertex colours; flat shading; no textures.
- **Palette:** warm sand/terracotta ground and walls, team accents only where they matter.

| Role | Colour |
|---|---|
| Gelin team | `#e0457b` (veil: white and gold) |
| Damat team | `#2f6fdb` (red fez `#b3261e`) |
| Band | `#3f8f6b` |
| Tiles | `#e9c892` / `#d9b274` |
| Dance floor | `#f3dfb6` / `#ecd0a0`, border `#b0553f` |
| Roofs | `#b3472f`, `#8f3a2c` |
| Gold accents | `#ffd35a` |

No AI-generated meshes or images are used; everything here is authored in code. AI output, if ever used,
is a draft only and must pass the checklist below.

## Assets

| File | Contents | Triangles | Notes |
|---|---|---|---|
| `character_gelin.glb`, `character_damat.glb`, `character_band.glb` | One rigged toy character (12 bones), 3 looks | ~500 each | Clips: `idle`, `halay`, `jump`, `dance_a`, `dance_b`, `rose_special`. One skinned mesh, one draw call. |
| `crowd.glb` | `CrowdBody` (tinted per instance) and `CrowdHead` | ~120 | Drawn with instancing. |
| `courtyard.glb` | Kit pieces: plaza, dance floor, 3 houses, lamp, 2 banners, stage, davul, zurna, wedding arch, planter | ~3.1 k | Each piece is a named node with its origin on the ground. |

Initial budgets (confirmed or revised by measurement in Step 1.7): character ≤ 1,500 triangles, crowd figure
≤ 260, courtyard kit ≤ 30,000, all GLBs together ≤ 5 MB, textures ≤ 1024².

## Per-asset validation checklist

Automated (Blender scripts and `assets.test.ts`):
- [x] Triangle count within budget
- [x] Scale and origin: feet / base on the ground, height in range
- [x] Rig: exactly 12 bones with the agreed names; same rig across character looks
- [x] Animation clips: exactly the agreed set, sensible lengths
- [x] One draw call per character and per kit piece; vertex colours present; no textures
- [x] Total download size

Manual (done by eye for every new or changed asset):
- [x] Readable at 540×960 and in the 9:16 broadcast (checked on 2026-11-23 with `?probe=1` screenshots)
- [x] Silhouette and colours consistent with the style guide (checked 2026-11-23)
- [ ] Animations loop and blend back into `idle` without popping (clips play in the scene; smoothness still to be judged on a live recording)
- [ ] Licence and provenance noted (everything so far is original, authored in these scripts)
